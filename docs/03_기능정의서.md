# 기능정의서

## 1. 시스템 구성

```
[Streamlit UI] ──> [Core 서비스(src/reportgen)] ──> [Claude API]
                         │
        ┌────────────────┼──────────────────────────┐
     ingest          library / analyze / generate   render
  (파일 추출)        (양식·사례·계획·실적·초안)       (HWPX 채우기, PDF)
                         │
                    validate (검증·근거보고서)
```

| 계층 | 기술 |
|---|---|
| UI | Streamlit |
| 언어 | Python 3.11+ |
| AI | Anthropic Python SDK (Claude API), 모델명은 설정 파일로 관리 |
| HWPX | `zipfile` + `lxml` (직접 구현) |
| HWP 읽기 | 한컴 자동화(`pyhwpx` 또는 `win32com`) → 실패 시 `pyhwp`(hwp5txt)/`olefile` |
| 기타 추출 | `pdfplumber`, `python-docx`, `openpyxl`/`pandas`, `Pillow` |
| PDF 변환 | 한컴 자동화 SaveAs PDF → LibreOffice(`soffice --headless`) + H2Orestart 확장 |
| 데이터 검증 | `pydantic` |
| 설정 | `python-dotenv`, `PyYAML` |

## 2. 처리 흐름

```
① 라이브러리 등록 (최초 1회 / 양식 변경 시)
   양식.hwpx ─> 필드 추출 ─> schema.yaml
   과거보고 ─> 텍스트 추출 ─> 필드별 분할 ─> extracted.md ─┐
                                              전체 분석 ─> style_profile.md

② 건별 작성
   계획안 ─┐
   자료들 ─┴> 추출(work/extracted) ─> 구조화(plan.json, actual.json)
          ─> 계획대비실적(comparison.json)
          ─> 필드별 초안(draft.json: 내용 + 근거 + 확인필요)
          ─> 검토·수정(UI) ─> 검증(validation.json)
          ─> 렌더(.hwpx) ─> PDF ─> 근거보고서.md
```

## 5. 주요 데이터 정의

### 5.1 schema.yaml (양식 필드)
```yaml
template_id: aiboot_result_v1
name: AIBOOT 결과보고 양식
fields:
  - key: 사업명
    type: text            # text | paragraph | table | image | date | number
    required: true
    source_hint: plan     # plan | actual | both | user
  - key: 추진성과
    type: paragraph
    guide: "3~5개 항목, 각 1~2문장, 수치 포함"
    max_chars: 600
  - key: 예산집행내역
    type: table
    columns: [비목, 계획액, 집행액, 집행률, 비고]
    row_marker: "{{#예산집행내역}}"   # 반복할 행에 표시
  - key: 활동사진
    type: image
    count: 4
```

### 5.2 draft.json (필드별 초안)
```json
{
  "fields": {
    "추진성과": {
      "value": "○ 교육 이수자 32명 배출(목표 30명 대비 106.7%)\n...",
      "sources": [{"file": "수료명단.xlsx", "loc": "Sheet1!A1:D33", "quote": "수료 32명"}],
      "needs_check": [],
      "status": "draft"          
    }
  }
}
```
`status`: draft → edited → confirmed

### 5.3 comparison.json
`항목, 계획, 실적, 단위, 달성률(코드 계산), 근거` 배열

## 6. 화면 정의 (Streamlit)

| 화면 | 구성 | 주요 동작 |
|---|---|---|
| S1 라이브러리 | 양식 목록, 과거 사례 목록, 문체 프로필 미리보기 | 양식/사례 업로드·삭제, schema 편집, 문체 프로필 재생성 |
| S2 새 결과보고 | 프로젝트 선택/생성, 양식 선택, 계획안·자료 업로드, 마스킹 옵션, 예상 비용 | [추출] → [구조화] → [초안 생성] 진행바 |
| S3 검토 | 좌: 필드 목록(상태 아이콘) / 중: 초안 편집 / 우: 근거·원문 / 상단: 계획대비실적 표, 검증 경고 | 수정, 필드 재생성(추가 지시), 확정 |
| S4 출력 | 검증 요약, 출력 파일명, 사진 선택 | [HWPX 생성] [PDF 변환] [폴더 열기] |

## 7. 핵심 로직 규칙

1. **숫자는 코드가 계산한다.** 달성률·합계·집행률은 Python으로 계산해 AI에 넘기고, AI는 문장만 쓴다.
2. **근거 우선.** 프롬프트에 "제공된 자료에 없는 사실은 쓰지 말고 `[확인 필요: 사유]`로 남길 것"을 명시한다.
3. **필드 단위 생성.** 한 번에 전체를 쓰지 않고 필드별로 호출해 길이·형식을 지키고 재생성을 쉽게 한다.
4. **Few-shot 예시.** 같은 필드의 과거 사례 문단 2~3개를 예시로 넣는다.
5. **HWPX 치환 순서.** ① run 병합 정규화 → ② 표 반복 행 처리 → ③ 텍스트 치환(XML 이스케이프) → ④ 이미지 → ⑤ `mimetype` 무압축 첫 항목으로 재압축.
6. **줄바꿈.** 문단 필드의 `\n`은 새 `<hp:p>` 문단으로 복제해 원래 문단 스타일을 유지한다.

## 8. 예외 처리

| 상황 | 처리 |
|---|---|
| .hwp인데 한컴 미설치 | 텍스트만 추출(pyhwp), "hwpx로 저장해 다시 올리면 표 인식이 정확해집니다" 안내 |
| 스캔 PDF(텍스트 없음) | Claude 비전으로 페이지 이미지 읽기(옵션), 아니면 경고 |
| API 오류/한도 | 재시도 후 실패 필드만 표시, 나머지는 유지 |
| AI JSON 형식 오류 | 스키마 오류 메시지를 붙여 최대 2회 재요청 |
| 생성 hwpx 열기 실패 | 원본 대비 XML diff 로그 저장, 텍스트만 치환한 안전 모드로 재생성 |
| PDF 변환기 없음 | hwpx만 출력, 한컴에서 PDF 저장 방법 안내 |
