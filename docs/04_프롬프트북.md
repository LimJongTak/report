# 프롬프트북 — VS Code + Claude Code로 ReportGen 만들기

이 문서의 프롬프트를 **순서대로** VS Code 터미널의 Claude Code에 붙여넣으면 프로그램이 단계별로 완성됩니다.
`<꺾쇠>` 부분만 본인 환경에 맞게 바꾸세요.

---

## 0. 사전 준비 (사람이 직접)

1. 설치: VS Code, Python 3.11 이상, Git, Node.js(LTS), Claude Code
   ```powershell
   npm install -g @anthropic-ai/claude-code
   ```
2. Anthropic API 키 발급 (console.anthropic.com) — 프로그램이 쓸 키입니다.
3. PDF 변환용 (둘 중 하나 이상)
   - 한컴오피스 2020 이상 (권장: 가장 정확)
   - LibreOffice + H2Orestart 확장 (한컴 없을 때)
4. 작업 폴더 만들기 → 이 키트의 `CLAUDE.md`와 `docs/` 폴더를 그대로 복사
   ```
   C:\dev\report-generator\
     ├─ CLAUDE.md
     └─ docs\01_과업지시서.md ... 04_프롬프트북.md
   ```
5. VS Code로 폴더 열기 → 터미널(Ctrl+`) → `claude` 입력

### 진행 요령
- 단계 하나가 끝나면 **동작 확인 → `git commit` → `/clear`** 후 다음 단계로 넘어갑니다. (대화가 길어지면 품질이 떨어집니다)
- 큰 단계는 먼저 **Plan 모드**(Shift+Tab 두 번)로 계획을 보고 승인하세요.
- Claude가 막히면 에러 메시지 전체를 그대로 붙여넣으세요.

## P0. 프로젝트 초기화

```
docs/ 폴더의 01_과업지시서.md, 02_요구사항명세서.md, 03_기능정의서.md를 모두 읽어줘.
그다음 03_기능정의서.md 4장 "폴더 구조"대로 프로젝트 뼈대를 만들어줘.

- 모든 폴더 생성 (빈 폴더에는 .gitkeep)
- src/reportgen 패키지와 하위 모듈 파일은 docstring과 함수 시그니처만 있는 빈 껍데기로
- requirements.txt (기능정의서 1장 기술 기준, 버전은 현재 안정 버전으로 고정)
- .env.example, .gitignore(.env, .venv, projects/*, library/templates/*/original.*, library/examples/*/source.*)
- config/settings.yaml (모델명, max_tokens, temperature, 마스킹 기본 ON, PDF 변환기 우선순위 [hancom, libreoffice])
  모델명은 Anthropic 문서에서 현재 권장 Sonnet 모델 ID를 확인해서 넣어줘
- app.py: Streamlit 4개 페이지(라이브러리/새 결과보고/검토/출력) 이동만 되는 빈 화면
- run.bat: .venv 활성화 후 streamlit run app.py
- README.md 초안

그다음 .venv 만들고 의존성 설치, git init, 첫 커밋까지 해줘.
마지막에 `streamlit run app.py`가 뜨는지 확인 방법을 알려줘.
```

**완료 확인:** 브라우저에 4개 메뉴가 있는 빈 화면이 뜬다.

## P1. 파일 추출기 (ingest)

```
요구사항 ING-01~06을 구현해줘. src/reportgen/ingest/ 아래에.

- base.py: 공통 결과 모델(pydantic) ExtractedDoc {file, type, blocks:[{kind: text|table|image, content, loc}]}
  loc는 "p.3", "Sheet1!A1:D10", "표2" 같은 위치 문자열
- hwpx.py: zip 열어서 Contents/section*.xml 파싱. 문단(hp:p/hp:run/hp:t)과 표(hp:tbl/hp:tr/hp:tc)를 구분해 추출
- hwp.py: Windows+한컴 있으면 pyhwpx(또는 win32com HWPFrame.HwpObject)로 .hwpx로 변환 후 hwpx.py 사용,
  없으면 pyhwp(hwp5txt)로 텍스트만. 어떤 경로를 썼는지 결과에 기록
- pdf.py(pdfplumber, 페이지별 텍스트+표), docx.py, sheet.py(xlsx/csv → 마크다운 표), text.py, image.py(EXIF 촬영일시, 크기)
- 확장자로 리더를 고르는 extract(path) 함수
- 결과를 work/extracted/<원본파일명>.md 로 저장하는 함수

tests/fixtures에 테스트용 최소 hwpx를 코드로 생성(또는 직접 만든 샘플)해서 pytest 작성, 전부 통과시켜줘.
```

**완료 확인:** `pytest` 통과, 샘플 파일 추출 결과 md가 읽을 만하다.

## P2. HWPX 채우기 엔진 (가장 중요)

> 먼저 한컴오피스에서 **실제 결과보고 양식을 열고**, 채울 칸마다 `{{사업명}}`, `{{추진성과}}`처럼 써넣은 뒤 `.hwpx`로 저장해 두세요.
> 표에서 데이터가 반복될 행은 첫 칸에 `{{#예산집행내역}}`처럼 표시합니다.

```
기능정의서 7장 5~6번 규칙에 따라 src/reportgen/render/hwpx_core.py, hwpx_filler.py를 구현해줘.

1) hwpx_core.py
   - HWPX(zip) 읽기/쓰기. 저장 시 mimetype을 무압축 첫 항목으로, 나머지 항목 순서·압축방식 유지
   - 한 문단 안에서 {{...}}가 여러 hp:run으로 쪼개진 경우 하나의 run으로 합치는 정규화
     (첫 run의 글자모양 charPrIDRef 유지)
   - 문서 안의 모든 {{필드}}와 {{#표필드}} 목록을 반환하는 함수
2) hwpx_filler.py: fill(template_path, data: dict, out_path)
   - text: XML 이스케이프 후 치환
   - paragraph: "\n" 기준으로 원래 hp:p를 복제해 여러 문단으로 (문단모양 유지)
   - table: {{#키}} 표시 행을 데이터 행 수만큼 복제, 각 셀의 {{열이름}} 치환, 표시 행 제거
   - image: 1차는 건너뛰고 TODO로 남김 (P7에서 구현)
   - 남은 {{ }}는 목록으로 반환

테스트용 양식은 아래 경로에 있어. 이 파일로 더미 데이터를 채워 output/test_filled.hwpx를 만들어줘.
양식 경로: <C:\경로\결과보고양식_마킹.hwpx>

내가 한컴오피스에서 열어보고 결과를 알려줄게. 열리지 않으면 원인을 XML diff로 추적해줘.
```

**완료 확인:** 한컴오피스에서 `test_filled.hwpx`가 오류 없이 열리고 서식이 그대로다.
안 열리면 → "한컴에서 '파일이 손상되었습니다'가 떠. 원본과 결과의 zip 항목 목록, mimetype 압축 여부, section0.xml diff를 비교해서 고쳐줘."

## P3. 라이브러리 등록 — ★ 내 양식·과거 보고서 경로를 넣는 단계

```
요구사항 LIB-01~10, 기능 F-01, F-03, F-04, F-05를 구현하고, 내 실제 자료로 라이브러리를 만들어줘.

[내 자료 경로]
- 결과보고 양식(마킹된 hwpx): <C:\경로\양식폴더>
- 과거 결과보고들: <C:\경로\과거결과보고폴더>
- (있다면) 과거 계획안들: <C:\경로\과거계획안폴더>

[해줄 일]
1. scripts/import_library.py 작성
   python scripts/import_library.py --templates <경로> --examples <경로> [--plans <경로>]
2. 양식마다 library/templates/<양식ID>/ 폴더를 만들고 original.hwpx, template.hwpx 복사,
   필드를 추출해 schema.yaml 생성. 필드 type/guide/max_chars는 과거 보고서의 실제 분량을 보고 추정해서 채워줘
3. 과거 보고서마다 library/examples/<연도_사업명>/ 폴더를 만들고 source 복사,
   텍스트 추출 → 양식 필드 단위로 나눈 extracted.md, meta.yaml(연도, 사업명, 사업유형, 양식ID) 생성.
   같은 사업의 계획안이 있으면 plan.md로 같이 넣어줘 (나중에 백테스트용)
4. prompts/style_profile.md 프롬프트를 만들고, Claude API로 과거 보고서 전체를 분석해
   library/style_profile.md 생성: 어미(~함/~임), 기호 체계(○, -, ※), 숫자·날짜 표기, 필드별 평균 분량,
   자주 쓰는 표현, 피해야 할 표현, 필드별 모범 문단 1개씩
5. src/reportgen/llm.py: Anthropic 클라이언트 래퍼(설정 파일의 모델, 재시도, 로그 저장, JSON 응답 파싱)

다 만든 뒤 실제로 스크립트를 실행하고, 생성된 schema.yaml과 style_profile.md를 보여줘.
경로의 파일이 .hwp면 P1의 hwp 처리 경로를 쓰고, 어떤 파일이 텍스트만 추출됐는지 표로 알려줘.
```

**완료 확인:** `library/` 아래에 양식·사례 폴더가 생기고 `style_profile.md` 내용이 우리 기관 문체와 맞다.
틀린 부분은 직접 고치거나 "style_profile.md에서 ○○를 △△로 바꿔줘"라고 요청.
