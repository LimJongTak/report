# 요구사항명세서 (SRS)

- 시스템명: ReportGen (결과보고 자동생성 프로그램)
- 우선순위: **M** = 필수(MVP), **S** = 권장(2차), **C** = 선택

## 1. 이해관계자 및 사용자

| 구분 | 설명 |
|---|---|
| 작성자 | 사업 담당자. 계획안과 자료를 넣고 초안을 검토·수정·출력 |
| 관리자 | 양식과 과거 결과보고를 라이브러리에 등록·관리 |
| 검토자 | 출력된 결과보고서와 근거 보고서를 확인 |

## 2. 기능 요구사항

### 2.1 라이브러리 관리 (LIB)

| ID | 요구사항 | 우선 |
|---|---|---|
| LIB-01 | 사용자는 결과보고 양식(.hwpx)을 이름을 붙여 등록할 수 있어야 한다. | M |
| LIB-02 | 시스템은 양식 안의 `{{필드명}}` 표시를 찾아 필드 목록(`schema.yaml`)을 자동 생성해야 한다. | M |
| LIB-03 | 필드는 유형(text, paragraph, table, image, date, number)과 설명·분량 가이드를 가질 수 있어야 한다. | M |
| LIB-04 | `{{ }}` 표시가 없는 빈 양식을 넣으면, 시스템이 라벨 셀/빈 셀 구조를 분석해 필드를 제안하고 표시된 양식 사본을 만들어야 한다. | S |
| LIB-05 | 사용자는 과거 결과보고서(.hwp/.hwpx/.pdf/.docx)를 등록할 수 있어야 한다. | M |
| LIB-06 | 시스템은 과거 보고서를 양식 필드 단위로 나눠 `extracted.md`로 저장해야 한다. | M |
| LIB-07 | 시스템은 과거 보고서 전체를 분석해 문체·어미·분량·표현 습관을 담은 `style_profile.md`를 생성해야 한다. | M |
| LIB-08 | 과거 보고서별로 메타정보(연도, 사업명, 사업유형, 사용 양식)를 기록해야 한다. | M |
| LIB-09 | 새 건 작성 시 사업유형이 비슷한 과거 사례를 우선 참고 예시로 고른다. | S |
| LIB-10 | CLI 명령으로 폴더 경로를 받아 양식·사례를 일괄 등록할 수 있어야 한다. | M |

### 2.2 프로젝트(건) 관리 (PRJ)

| ID | 요구사항 | 우선 |
|---|---|---|
| PRJ-01 | 사용자는 사업명·사용 양식을 지정해 새 프로젝트를 만들 수 있어야 한다. | M |
| PRJ-02 | 프로젝트별로 `input/plan`, `input/materials`, `work`, `output` 폴더가 자동 생성되어야 한다. | M |
| PRJ-03 | 이전 프로젝트를 다시 열어 이어서 작업할 수 있어야 한다. | M |

### 2.3 입력 및 추출 (ING)

| ID | 요구사항 | 우선 |
|---|---|---|
| ING-01 | 계획안 1개 이상, 결과 자료 여러 개를 업로드할 수 있어야 한다. | M |
| ING-02 | .hwpx, .pdf, .docx, .xlsx, .csv, .txt, .md에서 텍스트와 표를 추출해야 한다. | M |
| ING-03 | .hwp(바이너리)에서 텍스트를 추출해야 한다. 한컴오피스가 있으면 .hwpx로 자동 변환한다. | M |
| ING-04 | 이미지는 파일명·촬영일시(EXIF)를 기록하고, 사진 필드 후보로 등록해야 한다. | M |
| ING-05 | 이미지 내용 설명(캡션 초안)을 Claude 비전으로 생성할 수 있어야 한다. | S |
| ING-06 | 추출 결과는 원본 파일명·페이지/시트 위치와 함께 `work/extracted/`에 저장해야 한다. | M |

### 2.4 분석 및 생성 (GEN)

| ID | 요구사항 | 우선 |
|---|---|---|
| GEN-01 | 계획안에서 사업명, 목적, 기간, 장소, 대상, 목표 인원, 세부 프로그램, 예산 항목을 구조화(JSON)해야 한다. | M |
| GEN-02 | 결과 자료에서 실제 일시, 참여 인원, 집행액, 만족도, 성과 등을 구조화해야 한다. | M |
| GEN-03 | 계획 대비 실적 비교표(항목, 계획, 실적, 달성률, 비고)를 자동 계산해야 한다. | M |
| GEN-04 | 양식 필드별로 초안을 생성하되, 과거 사례 문체(`style_profile.md`)와 예시 문단을 반영해야 한다. | M |
| GEN-05 | 각 필드 초안에는 사용한 근거(파일명, 위치, 인용)가 함께 기록되어야 한다. | M |
| GEN-06 | 근거가 없는 내용은 만들어내지 않고 `[확인 필요: 사유]`로 표시해야 한다. | M |
| GEN-07 | 사용자는 필드 단위로 다시 생성하거나, 추가 지시("더 짧게", "성과 강조")를 줄 수 있어야 한다. | M |
| GEN-08 | AI 출력은 정해진 JSON 스키마를 따르며, 형식이 깨지면 자동 재시도(최대 2회)해야 한다. | M |
| GEN-09 | 금액은 천 단위 쉼표, 날짜는 양식 관례(예: 2026. 11. 12.(목))로 통일해야 한다. | M |

### 2.5 검토 및 검증 (VAL)

| ID | 요구사항 | 우선 |
|---|---|---|
| VAL-01 | 화면에서 필드별 초안, 근거, 수정란을 나란히 보여줘야 한다. | M |
| VAL-02 | 초안에 있는 모든 숫자가 입력 자료에 존재하는지 점검하고, 없으면 경고해야 한다. | M |
| VAL-03 | 미치환 `{{ }}`, `[확인 필요]` 개수, 빈 필수 필드를 출력 전에 보여줘야 한다. | M |
| VAL-04 | 예산 합계, 인원 합계 등 계산값의 일치 여부를 점검해야 한다. | M |
| VAL-05 | 검증 결과와 필드별 근거를 `근거보고서.md`로 저장해야 한다. | M |

### 2.6 출력 (OUT)

| ID | 요구사항 | 우선 |
|---|---|---|
| OUT-01 | 확정된 내용으로 양식 `.hwpx`를 채워 `output/`에 저장해야 한다. | M |
| OUT-02 | 표 필드는 데이터 행 수만큼 행을 복제·삭제해야 한다. | M |
| OUT-03 | 사진 필드에 선택한 이미지를 삽입해야 한다(크기 자동 맞춤). | S |
| OUT-04 | `.hwpx`를 PDF로 변환해야 한다. 한컴오피스 자동화 → LibreOffice+H2Orestart 순으로 시도한다. | M |
| OUT-05 | 출력 파일명은 `YYYYMMDD_사업명_결과보고.hwpx` 규칙을 따른다. | M |
| OUT-06 | PDF 변환이 불가능하면 이유와 수동 변환 방법을 안내해야 한다. | M |

## 4. 제약사항 및 가정
- 양식은 `.hwpx`를 기준으로 한다. `.hwp` 양식은 한컴오피스에서 "다른 이름으로 저장 → HWPX"로 바꿔 등록한다.
- HWPX는 ZIP+XML(OWPML) 구조이며, `mimetype` 파일은 압축하지 않고 ZIP의 첫 항목이어야 한다.
- 한 단어처럼 보이는 `{{필드}}`가 XML에서 여러 run으로 쪼개질 수 있으므로 치환 전에 정규화가 필요하다.
- Claude API 사용료가 발생한다.

## 5. 인수 시나리오 (요약)
1. 관리자가 양식 1개와 과거 결과보고 3개를 CLI로 일괄 등록 → `schema.yaml`, `style_profile.md` 생성 확인
2. 작성자가 새 프로젝트 생성 → 계획안(.hwp) + 명단(.xlsx) + 지출내역(.xlsx) + 사진 5장 업로드
3. 초안 생성 → 계획 대비 실적 표, 필드별 초안과 근거 확인 → 2개 필드 수정, 1개 재생성
4. 검증 경고 0건 확인 → hwpx + PDF 출력 → 한컴오피스에서 정상 열림 확인
